# Colour palette / swatch
> NOTE: The colours in the swatch below are **NOT** being updated by [Storybook Design Token addon](https://github.com/UX-and-I/storybook-design-token) when switching between themes, but component stories are updated.

## Dark mode
- Colours in the component stories will be updated automatically if the operating system preference for `dark mode` is selected. This triggers the CSS `prefers-color-scheme: dark` media query and/or `light-dark()` function.
- Specific dark mode colour tokens can also be defined in `./ui/src/css/tokens.css`.

### Storybook dark mode addon
- This Storybook addon allows you to toggle between light (default) and dark mode manually in the Storybook UI.

> NOTE: The Storybook UI and stories switch to dark mode, but docs pages are rendered in light mode. There is a workaround in `ui/public/storybook-overrides.css` to ensure docs text is legible.

## Using `OKLCH()` to define colours
> See [why OKLCH is better than HSL](https://evilmartians.com/chronicles/oklch-in-css-why-quit-rgb-hsl) and [OKLCH color picker tool](https://oklch.com/#70,0.1,293,100).

- For example, primitive tokens are declared like this (notice the use of [relative colors](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Colors/Using_relative_colors) to increase the **lightness** of `--color-brand-100`):
```
:root {
    --color-brand: oklch(44.03% 0.1603 303.37);
    --color-brand-100: oklch(from var(--color-brand) calc(l + 0.3) c h);
}
```
- Semantic tokens are declared like this:
```
:root {
    --webui-color-primary-500: var(--color-brand);
    --webui-color-primary-100: var(--color-brand-100);
}
```
